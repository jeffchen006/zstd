Independent longer confirmation:
Select a named case with --case, --rounds 5 --seconds 5 --skip-aa. The experiment always confirmed silesia-L9 and the worst screened loss below-1% for each compiler, using fresh samples. This selection rule was written before the confirmation results. Three original L6 file-loss cases use five pairs at-i5.

Same-binary controls:
Use the SAME baseline executable for both --baseline and --candidate, with --case silesia-L9 --rounds 5 --seconds 5 --skip-aa. The x86 random-data concern also has five data-matched A/A pairs on random16MiB-L9. Do not use a Silesia-only noise estimate as proof of random-data stability. The initial Mac A/A overlapped data staging and is excluded; the later controls are separate. All other recorded values, including large outliers, remain in the evidence.

Streaming scenario:
In this pinned source, tests/fullbench.c kScenarios index7 is compressStream:
  tests/fullbench -b7 -l9 -i3 enwik8-first-1024
The historical mergedPR #3543 used-b41. ID41 no longer exists and silently returns0 without a timing. Require a nonempty compressStream result and no validation failure; returncode0 alone is insufficient.

Linux placement/load controls:
This experiment used taskset -c62, with SMT sibling158 idle, and rejected timing samples when the benchmark process received less than93% scheduled CPU or its sibling was more than10% busy. Choose an appropriate available core for a new machine; do not blindly use these CPU numbers. No unrelated job was paused and no governor/boost/ASLR setting changed. A shared host still has uncontrolled cache, memory and frequency variation.

Fixed-work counters (NOT adaptive-loop instruction totals):
  taskset -c62 perf stat -x, -e cycles,instructions,branches,branch-misses,cache-misses,context-switches,cpu-migrations /path/to/zstd -q -9 --single-thread --no-asyncio --no-check -c silesia-all > /dev/null
Run five alternating pairs with the same fixed input. Ordinary CLI default worker counts differ from benchmark defaults, so --single-thread is explicit. Earlier exploratory counter runs without the explicit flag are excluded from the final mechanism evidence.
The random-data instruction diagnostic repeats the seeded16MiB source16times(256MiB) and uses --zstd=wlog=22. The explicit4MiB window prevents matching the16MiB repetition distance and matches default level9's window in this pinned source. This is a diagnostic workload, not another sample of the original16MiB throughput experiment.

Profiling:

Profile/counter invocations are excluded from throughput summaries; adaptive-loop profile sample counts are not used as instruction-count ratios.

Local static analysis:
Use fresh separate source exports and the official LLVM scan-build wrapper pinned llvmorg-20.1.8 with the installed AppleClang17 analyzer. Supply CC through the ENVIRONMENT so recursive make permits interception:
  env CC=/path/to/clang make staticAnalyze 'SCANBUILD=/path/to/scan-build --use-analyzer=/path/to/clang --use-cc=/path/to/clang -v -v --keep-empty -o /new/analysis-reports'
Check real clang-cc1 -analyze invocations, including zstd_lazy.c, and diagnostics. A build that is already up to date or a command-line CC override can yield a misleading no-bugs wrapper message without analyzing the source. Our actual runs analyzed41units each and all exit2 with the same12inherited diagnostics; no new reports. No checker was disabled to turn this into a clean pass.
